### Импорт PasarGuard и 3x-ui

Перед импортом остановите запись в исходную панель и сделайте резервную копию
целевой базы GoWave. Выполняйте команды из рабочего каталога GoWave с его `.env`.
Импорт читает источник и записывает данные одной транзакцией: ошибка отменяет
все изменения. Сначала рекомендуется импорт в отдельную тестовую базу.

```sh
gowave-server import pasarguard /path/to/backup.zip
gowave-server import pasarguard /path/to/db.sqlite3
gowave-server import pasarguard 'postgresql://user:password@localhost/pasarguard'
gowave-server import 3x-ui /etc/x-ui/x-ui.db
```

Те же операции доступны в rescue-меню (7 и 11). Для PasarGuard ZIP должен
содержать `db.sqlite3` в корне; вложенные старые копии не импортируются.
Без пути используется существующее автоопределение PasarGuard, для 3x-ui —
`/etc/x-ui/x-ui.db`. URL с паролем не выводится импортером в журнал.

PasarGuard: переносятся пользователи, совместимые протокольные пароли/UUID,
лимиты, сроки, заметки, HWID и время их использования, отзыв подписки,
текущий/накопленный трафик, время онлайн, Xray-профили и inbound-ы, группы
и связи пользователей/inbound-ов, основные параметры хостов, ноды,
история трафика нод/пользователей и запросов подписки. Числовые ID
переназначаются с сохранением связей. Повторный импорт обновляет пользователей
по имени, остальные объекты — по стабильным идентификаторам; он заменяет
соответствующие данные актуальным состоянием источника. Не переименовывайте
импортированные записи между повторами. Пользователи `on_hold` импортируются
отключёнными: отложенная активация требует ручного переноса.

Ноды PasarGuard импортируются отключёнными: нужно установить GoWave Node
и настроить подключение. Сертификаты/API-ключи RPC PasarGuard несовместимы.
Администраторы, роли/права, JWT, ключи API, уведомления, настройки панели,
шаблоны подписок с другим движком, планы продления и специфические параметры
хостов без аналога требуют ручной конвертации. Старые ссылки PasarGuard
не сохраняются: GoWave создаёт собственные идентификаторы подписок.

3x-ui: поддерживаются клиенты VLESS, Trojan и Shadowsocks, их учётные данные,
байтовые лимиты (`totalGB` в базе уже содержит байты), абсолютный срок в
миллисекундах, статус, Telegram ID, комментарий, `subId`, счётчики трафика,
Xray inbound-профили и отдельные внутренние группы. Схема проверена по
исходникам 3x-ui v2.8.5; реальная база 3x-ui пока не проверялась. Клиентам с общим `subId` назначаются отдельные токены после первого клиента;
это сохраняет разные учётные данные, но требует выдачи новых ссылок. Клиенты
с конфликтующими именами/паролями, неподдерживаемые
протоколы и отрицательный отложенный срок вызывают откат импорта. IP-лимиты
не преобразуются в HWID-лимиты. Произвольные периоды сброса, настройки панели,
логины администраторов и внешняя конфигурация Nginx из x-ui-pro переносятся
вручную. Создайте публичные хосты и подключите GoWave Node перед запуском.
Сохранение `subId` сохраняет токен, но домен и маршрут старой ссылки могут
потребовать перенастройки reverse proxy.
